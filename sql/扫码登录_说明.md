## 一、先说清三个页面 —— 太容易搞混

| 页面 | 方向 | 谁在这页上 | 干什么 |
|---|---|---|---|
| `Beta/login-Beta.html` | A | 电脑（**未**登录） | 多了个「📱 扫码」标签，显示二维码 |
| `Beta/qr-login-Beta.html` | A | **手机（已登录）** | 扫码后确认「给这台电脑授权」 |
| `Beta/profile-Beta.html` | B | 电脑（已登录） | 多了一块「📱 登录其他设备」入口 |
| `Beta/qr-grant-Beta.html` | B | 电脑（已登录） | 生成二维码给人扫 |
| `Beta/qr-claim-Beta.html` | B | **手机/别的设备（未登录）** | 扫码后确认「登录这台设备」 |

**记法：**
- **`login`** 系列 = 手机已登录 → 授权电脑（电脑要**登**进来）
- **`grant` / `claim`** 系列 = 电脑已登录 → 发登录给别人（电脑在**授权**）

## 二、方向 A：手机授权电脑

**解决什么**：电脑上收邮件、输 6 位验证码麻烦。

```
电脑(未登录)                          手机(已登录)
────────────                          ────────────
点「📱 扫码」
  │
  ├─ qr_login_create → code + secret
  ├─ 显示二维码(码里只有 code)
  │
  ├─ 每 2 秒 qr_login_poll(code, secret)
  │                                     打开相机扫码
  │                                       │
  │                                       ├─ qr_login_scan(code)
  │                                       │   → 显示"请求登录的设备"
  │                                       │      IP / 浏览器 / 时间
  │                                       │
  │                                       └─ 点「✅ 确认登录」
  │                                          qr_login_confirm(code, 我的id, 我的session)
  │
  └─ poll 返回 status='ok' + 令牌
       → 存 localStorage → 电脑登录完成
```

### 安全设计

**① `code` 和 `secret` 分开 —— 偷看二维码没用**

```
code    放进二维码，谁看到都能拿到
secret  只在 create 时返回给那台电脑，轮询要用
```

**会话令牌只发给同时持有 `secret` 的那台电脑。** 别人偷看到二维码，最多"替他确认一次登录"，**拿不到最后的令牌**。

**② 手机确认前必须先看到"是谁在请求"** ⚠️

扫码登录天然有一个钓鱼面（业内叫 **QRLJacking**）：

> 攻击者在**自己电脑**上生成二维码 → 发给受害者 → 受害者扫码并确认 → **攻击者那台电脑登进了受害者的账号**

**这个挡不住**（用户自己点了确认）。但可以让他在点之前看清楚：

```
浏览器   Chrome · Windows
IP       1.2.3.4
请求时间  14:23:05

⚠️ 如果不是你自己正在用的设备，请不要点确认。
   别人可以把二维码发给你，骗你扫码替他登录。
```

> **浏览器那行是电脑端传上来的，可以伪造；`IP` 是服务端自己读的（`_request_ip()`），伪造不了 —— 所以以 IP 为准。** 代码注释里标了。

## 三、方向 B：电脑授权设备

**解决什么**：手机上打字慢，不想再输一遍用户名 + 密码。

```
电脑(已登录)                          手机/别的设备(未登录)
────────────                          ─────────────────
个人主页 →「📱 登录其他设备」
  │
  ├─ qr_grant_create(我的id, 我的session, ua)
  ├─ 显示二维码
  │
  ├─ 每 2 秒 qr_grant_status(code, secret)
  │                                     打开相机扫码
  │                                       │
  │                                       ├─ qr_grant_info(code)
  │                                       │   → "你将登录为 N***方"
  │                                       │      + 还有多少秒有效
  │                                       │
  │                                       └─ 点「✅ 确认登录这台设备」
  │                                          qr_grant_claim(code)
  │                                          → 直接拿到令牌 → 这台设备登录
  │
  └─ 显示"已被领走" + 对方的 IP / 浏览器 / 时间
```

### ⚠️ 安全模型和 A **完全不同**

| | 方向 A | 方向 B |
|---|---|---|
| `code` 是什么 | "请求登录"的凭据 | **就是登录凭证本身** |
| 偷看到二维码 | 拿不到令牌 | **就能登进这个账号** |
| 有效期 | 2 分钟 | **90 秒**（更短） |
| 谁生成的 | 任何人（未登录也行） | **必须已登录** |

**所以 B 方向做了这些：**

- 电脑端**显著警告**：「这个二维码等于一次登录凭证，别截图、别发给任何人」
- 有效期只给 **90 秒**
- **一次性**：`UPDATE ... WHERE status='pending' RETURNING` 原子抢占
- 领走后**显示对方的 IP**，号主能发现异常
- 手机端先显示「你将登录为 **N\*\*\*方**」（账号名做遮挡），让人看清再点

> **B 方向最现实的攻击是**：用户把二维码截图发到群里问"这个怎么用不了"，被人抢先扫走。
> 所以警告文案写得比较重。

## 四、服务端（`sql/qr_login.sql`）

一张表装两个方向，用 `kind` 区分。

**表 `qr_login_sessions`**

| 列 | 说明 |
|---|---|
| `kind` | `pc_login`（方向A）/ `device_login`（方向B） |
| `code` | 16 位十六进制，放进二维码 |
| `secret` | 32 位十六进制，**只在方向 A 用**，不进二维码 |
| `status` | pending / confirmed / consumed / cancelled |
| `user_id` | A：确认的账号　B：授权人（创建时就写） |
| `desktop_ua` / `desktop_ip` | 浏览器那一侧 |
| `claim_ip` / `claim_ua` | B 专用：哪台设备领走的 |

**9 个接口**

| 方向 | 函数 | 谁调 |
|---|---|---|
| A | `qr_login_create(p_ua)` | 电脑 |
| A | `qr_login_scan(p_code)` | 手机（看是谁在请求） |
| A | `qr_login_confirm(p_code, p_user_id, p_session, p_approve)` | 手机 |
| A | `qr_login_poll(p_code, p_secret)` | 电脑（拿令牌） |
| B | `qr_grant_create(p_user_id, p_session, p_ua)` | 电脑 |
| B | `qr_grant_info(p_code)` | 手机（看会登成谁） |
| B | `qr_grant_claim(p_code, p_ua)` | 手机（领令牌） |
| B | `qr_grant_status(p_code, p_secret)` | 电脑（看有没有被领走） |
| 公共 | `qr_login_cancel(p_code, p_secret)` | 两边都能调 |

**其它细节**

| | |
|---|---|
| 建会话限频 | A：同一 IP 10 分钟 8 个　B：同一账号 10 分钟 10 个 |
| 过期清理 | 每次建会话顺手删 1 小时前的记录，表不会一直涨 |
| 表权限 | `REVOKE ALL ... FROM anon, authenticated`，匿名只能通过函数操作 |
| 令牌只发一次 | `UPDATE ... WHERE status='confirmed'/'pending' RETURNING` 原子抢占 |
